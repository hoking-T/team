# 智慧仓储物流协同系统（WMS）

面向《软件工程实验》实验项目的可运行原型系统：覆盖 **入库 → 库存 → 盘点 → 拣选 → 出库 → 物流协同** 全链路，采用 **事件驱动 + RBAC 权限控制** 架构。

- 后端：Python 3.8+ 标准库（`http.server` + `sqlite3`），**零第三方依赖，不需要 pip install**
- 前端：原生 HTML / CSS / JavaScript，由后端同一端口提供服务
- 数据库：SQLite（单文件 `wms.db`，首次运行自动建表并写入演示数据）

---

## 一、运行方法

### 方式 1：双击启动（推荐）
双击文件夹中的 **`启动.bat`**，浏览器会自动打开 `http://localhost:8000`。

### 方式 2：命令行启动
```bat
cd /d D:\智慧仓储物流协同系统
python app.py
```
看到 `智慧仓储物流协同系统 已启动` 后，访问 <http://localhost:8000>。停止服务按 `Ctrl + C`。

> 若 8000 端口被占用，可先设置环境变量更换端口：
> `set WMS_PORT=8080` 后再执行 `python app.py`

## 三、功能模块（对应实验指导书的 4 个 Sprint）

| 模块 | 主要功能 | 对应验收点 |
|---|---|---|
| 登录与权限 | 登录鉴权、Token 会话、角色权限配置（7 类权限） | Sprint 1：RBAC 权限控制 |
| 基础数据 | 仓库、库位、商品 SKU、供应商的增删查，含安全库存 | Sprint 1：基础数据管理 |
| 入库管理 | 创建入库单 → 收货验货（实收/合格数量）→ 指定库位上架 → 自动生成库存与流水 | Sprint 2：入库全流程 |
| 库存管理 | 实时库存（按仓库/关键字查询、锁定数量）、库存预警、盘点（生成→录入→审核调整）、库存流水 | Sprint 2：库存与盘点一致性 |
| 拣选作业 | 出库单自动按库位拆拣货任务、扫码式拣货确认、任务状态流转 | Sprint 3：拣选作业 |
| 出库与物流 | 出库单创建（自动锁库存/校验库存不足）→ 复核 → 确认出库 → 生成运单 → 调用承运平台推送（支持失败重试）→ 轨迹同步与异常预警 | Sprint 3 / 4：外部系统对接、可追溯 |
| 系统管理 | 用户管理、角色权限、业务事件日志、操作日志 | Sprint 1 / 4：可追溯与日志 |
| 工作台 | 库存总量、待办数量、库存预警、业务事件流 | Sprint 4：端到端验证 |

### 事件驱动设计
业务动作完成后发布领域事件，事件总线统一消费并持久化到 `business_events` 表，前端「系统管理 → 业务事件」可实时查看：

| 事件 | 触发时机 | 消费者动作 |
|---|---|---|
| `InboundOrderCreatedEvent` | 创建入库单 | 记录单据、通知收货待办 |
| `InboundAcceptedEvent` | 收货验货完成 | 更新入库进度 |
| `GoodsInEvent` | 上架入库 | 增加库存、写库存流水 |
| `PickFinishEvent` | 拣货确认 | 出库单累计已拣数量、流转状态 |
| `OrderShipEvent` | 确认出库 | 生成运单、推送承运平台 |
| `LogisticsPushEvent` / `LogisticsPushFailedEvent` | 运单推送成功/失败 | 记录物流状态、进入重试队列 |
| `LogisticsAbnormalEvent` | 轨迹与目的地偏离 | 触发异常预警流程 |
| `StockChangeEvent` | 盘点审核调整 | 修正库存、留痕 |

## 五、主要接口（REST / JSON）

统一返回格式：`{"ok": true, "data": ...}` 或 `{"ok": false, "msg": "错误原因"}`；
鉴权头：`Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 登录，返回 token 与权限集合 |
| GET | `/api/dashboard` | 工作台统计、预警、事件 |
| GET/POST | `/api/warehouses`、`/api/locations`、`/api/products`、`/api/suppliers` | 基础数据 |
| GET/POST | `/api/inbound` | 入库单列表 / 创建 |
| POST | `/api/inbound/{id}/receive` | 收货验货 |
| POST | `/api/inbound/{id}/putaway` | 上架入库 |
| GET | `/api/inventory`、`/api/inventory/warning` | 库存查询 / 预警 |
| GET | `/api/stock-moves` | 库存流水 |
| GET/POST | `/api/checks` | 盘点单列表 / 生成 |
| POST | `/api/checks/{id}/input`、`/api/checks/{id}/approve` | 录入实盘 / 审核调整 |
| GET/POST | `/api/outbound` | 出库单列表 / 创建（自动锁库存、拆拣货任务） |
| GET | `/api/pick-tasks`，POST `/api/pick-tasks/{id}/confirm` | 拣货任务 / 确认 |
| POST | `/api/outbound/{id}/review`、`/api/outbound/{id}/ship` | 复核 / 确认出库并推送 |
| GET | `/api/waybills`，POST `/api/waybills/{id}/push`、`/sync` | 运单、重试推送、同步轨迹 |
| GET | `/api/waybills/{id}/trace` | 物流轨迹 |
| GET/POST/PUT/DELETE | `/api/users` | 用户管理（需系统管理权限） |
| GET/PUT | `/api/roles` | 角色权限配置 |
| GET | `/api/events`、`/api/logs` | 业务事件 / 操作日志 |

## 六、完整业务演示路径（建议按此顺序验收）

1. 用 `admin / admin123` 登录 → 工作台查看库存总量与待办。
2. 「基础数据 → 商品 SKU」新增一个商品，设置安全库存。
3. 「入库管理 → 新建入库单」选择供应商与商品（如 50 件）→ 提交。
4. 点「收货验货」，实收 50、合格 48（模拟 2 件残次）→ 提交。
5. 点「上架」，选择库位 → 确认，库存增加 48，系统管理内出现 `GoodsInEvent`。
6. 「库存管理 → 库存预警」可见低库存商品；「盘点管理」生成盘点单 → 录入实盘（改 1 条）→ 审核调整。
7. 「出库与物流 → 新建出库单」填写客户与数量（数量超过库存会被拦截）。
8. 「拣选作业」按库位任务点「扫码确认」→ 回到出库单点「复核」→「确认出库」。
9. 承运商选「德邦物流(模拟异常)」可演示**推送失败**；选「顺丰速运」则推送成功，进入「运单与物流轨迹」→「同步轨迹」查看节点，最终「已签收」。
10. 「系统管理」查看业务事件流与操作日志，验证全链路可追溯。

## 八、常见问题

| 问题 | 处理 |
|---|---|
| 页面打不开 | 确认命令行窗口未关闭；访问 `http://localhost:8000` 而非文件路径 |
| 端口被占用 | `set WMS_PORT=8080` 后重新启动 |
| 想恢复演示数据 | 关闭服务 → 删除 `wms.db` → 重新启动（自动重建种子数据） |
| 中文乱码 | 页面与接口均为 UTF-8；若命令行乱码属终端编码问题，不影响系统 |
