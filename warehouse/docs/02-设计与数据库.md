# 二、设计规格说明书

## 架构比较
|方案|开发/部署成本|一致性|事件特点|结论|
|---|---|---|---|---|
|模块化单体+同步进程内事件|一个Java服务、一份数据库，适合5人初学组|同一数据库事务强一致|真实publishEvent/EventListener，无独立队列|采用|
|微服务+消息队列+独立数据库|多个服务、队列、部署及调试，学习成本高|需Outbox、重试、幂等、最终一致|异步跨服务，适合扩容|超出首版范围|
|简单单体直接调用物流|成本最低|同库事务方便|订单直接依赖物流实现|不选，削弱选题事件解耦目标|

Spring Boot 3.5.7 / Spring MVC / JDBC / H2 2.3.232（由依赖管理锁定）/ Bean Validation / JUnit5；前端原生HTML、CSS、JS，fetch连接后端。不引入Node构建，适合阅读；未采用Bootstrap并不影响基本网页实现。pom声明Java17语言级别，本机运行JDK25.0.1。
逻辑包图04-packages；部署图05-deployment。浏览器HTTP→控制器→模块服务→JDBC→文件数据库；服务发布事件，监听器调用物流。物联网以虚线“未来”展示：扫码枪/传感器→网关→未来设备接入适配器，不冒充已有硬件集成。

## 事务、并发与事件
- CatalogService.create 建商品并为所有预置货位建零库存行，一个事务内完成，避免首次入库并发插入同键。
- InventoryService.receive 原子UPDATE累加，带上限条件；随后写入库单及STOCK_RECEIVED事件审计。
- OrderService.create仅建PENDING订单，发布ORDER_CREATED，不预占库存。
- OrderService.ship首先SELECT FOR UPDATE锁订单，检查PENDING；条件UPDATE `quantity>=需求`扣减，再改SHIPPED；发布STOCK_SHIPPED与ORDER_SHIPPED。
- EventHandlers为同步@EventListener，MANDATORY要求已有事务；存event_log后处理物流生成。没有@Async，也不是提交后监听。监听失败不吞异常，由Spring回滚库存、订单、事件、物流及轨迹。故障排除后重试确认出库即可。
- LogisticsService.createForOrder锁同一订单，检查SHIPPED和已有物流，order_id唯一约束兜底；初始轨迹WAITING。advance锁物流，验证相邻状态，更新与轨迹同事务。
- 同一事件ID顺序重放直接返回；新事件ID也通过订单锁与唯一物流约束避免重复生成。相同事件ID并发重放可能发生唯一键冲突，失败事务需重试，不保证每个并发请求都成功返回；不会产生重复业务结果。
- 事件记录不是待投递队列：进程崩溃未提交则整体撤销，已提交则业务与审计一起保存。本版没有后台自动重试或跨进程投递。接真实物流时不应在数据库事务内长时间等待外网，应改事务Outbox+异步重试+接收端幂等，属于后续设计。
- 入库和创建订单没有客户端幂等请求键，网络中断导致结果不明时先查询记录再重试；页面刷新失败会提示核对，不能承诺所有HTTP重试都是幂等。

|实体/记录|控制类|边界类|责任|

## 数据库设计
类→表；库存为商品和货位的关联实体，复合主键；订单和物流1:0..1使用唯一外键；物流和轨迹1:N。实际初始化源 `src/main/resources/schema.sql`，只建不存在的表和货位，不删除业务数据。无自动迁移工具；修改已有表结构须新增迁移方案，不能指望CREATE IF NOT EXISTS更新旧表。

下表使用简写：PK主键、FK外键、U唯一、NN非空。BIGINT有符号64位、整数精度19/小数位0；VARCHAR宽度为字符上限；TIMESTAMP WITH TIME ZONE带时区，默认时间精度6。所有字段均NN，无隐式可空字段。未单列默认值时无业务默认（自增主键除外）。

|表|字段（中文）|类型|键/默认/约束|
|---|---|---|---|
|product 商品|id 编号|BIGINT|PK，自增|
|product|code 业务编号|VARCHAR(40)|U；API限制字母数字_-并大写|
|product|name 名称|VARCHAR(100)|API非空白|
|product|unit 单位|VARCHAR(20)|API非空白|
|location 货位|id 编号|BIGINT|PK，预置1/2/3|
|location|code 货位码|VARCHAR(20)|U；A01/A02/B01|
|stock 库存|product_id 商品|BIGINT|复合PK，FK product.id|
|stock|location_id 货位|BIGINT|复合PK，FK location.id|
|stock|quantity 库存数|BIGINT|默认0；CHECK 0—1000000000|
|inbound 入库单|id 单号|BIGINT|PK，自增|
|inbound|product_id 商品|BIGINT|FK product.id|
|inbound|location_id 货位|BIGINT|FK location.id|
|inbound|quantity 入库数|BIGINT|CHECK 1—1000000|
|inbound|created_at 入库时间|TIMESTAMP WITH TIME ZONE|默认CURRENT_TIMESTAMP|
|outbound_order 出库单|id 单号|BIGINT|PK，自增|
|outbound_order|product_id 商品|BIGINT|FK product.id|
|outbound_order|location_id 货位|BIGINT|FK location.id|

|event_log|created_at 处理时间|TIMESTAMP WITH TIME ZONE|默认CURRENT_TIMESTAMP|

索引：每表主键自动索引；product.code、location.code、shipment.order_id以及tracking(shipment_id,status)唯一索引由H2命名；显式普通索引ix_order_product(product_id)、ix_inbound_product(product_id)、ix_tracking_time(shipment_id,created_at,id)。外键可能由H2自动创建支持索引，不依赖其内部名称。H2使用MVStore文件，不为每个SQL索引单列“索引文件”，不声明MySQL聚集索引特性。
库存、入库、出库均引用既有商品货位；不开放删除，外键默认限制破坏引用。编号重复由数据库U保证，空白名称由API校验保证（数据库NN并不阻止空字符串）。状态转换规则由服务保证，CHECK只限定可取值。
