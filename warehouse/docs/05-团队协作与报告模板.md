## Git协作（不需要先有GitHub）
本目录若已初始化，则直接使用；否则IDEA菜单VCS→Enable Version Control→Git，或终端`git init -b main`。本次不代填组员姓名邮箱、不伪造提交。
1. 每位成员在自己电脑配置真实身份：`git config user.name "自己的姓名"`，`git config user.email "自己的邮箱"`。先`git status`检查。
2. 指定一人审核初稿后创建真实基线提交：`git add .`、`git commit -m "chore: review initial warehouse baseline"`。JAR在release用于演示；target、data、.tools、IDE文件已忽略。
3. 团队选择GitHub/GitLab/Gitee任一平台建立真实远程仓库（还没建不影响本地学习）。仓库所有者设置origin并push，其余成员clone。不要复制别人的.git文件夹作为自己的修改记录。
4. 工作前`git switch main`、`git pull --ff-only`；新任务`git switch -c feature/product-filter`。改少量文件、跑测试、`git diff`核对，再`git add 路径`与`git commit -m "feat: add product name filter"`。
5. `git push -u origin feature/product-filter`，创建合并请求，由另一成员审查测试与文档后合并；本地无远程时也可用分支练习和线下评审。
6. 冲突先看两边含义再编辑，测试通过后提交，不要使用强推或直接覆盖队友文件。提交说明可用feat/fix/test/docs，写实际发生的修改。
7. 保存`git log --oneline --graph --all`、合并请求链接、任务记录作为证据；不能把AI一次生成拆成假装跨周的提交，更不能冒用组员身份。

若Windows终端找不到git，重开IDEA/终端，或使用已确认的 `C:\Program Files\Git\cmd\git.exe`。仓库不包含数据库；分享前停止服务并单独备份data供演示，不把实际业务数据长期提交到Git。
